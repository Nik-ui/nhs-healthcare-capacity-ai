# Hackathon Compliance

This document explains how NHS Capacity Memory Agent maps to the CockroachDB x AWS Hackathon requirements.

## Project Requirement

The project is an NHS capacity decision-support application that uses CockroachDB as its memory layer and is deployed with AWS.

The agent can:

- answer questions about NHS capacity pressure
- retrieve regional bed occupancy data
- retrieve A&E activity history
- produce a short-term A&E pressure forecast
- remember previous questions and answers
- retrieve similar previous memories using vector search

## CockroachDB Tools Used

### 1. CockroachDB Cloud

CockroachDB Cloud stores the project data and agent memory.

The database contains:

- `capacity_snapshots`
- `beds_region_sector`
- `ae_activity`
- `agent_memory`
- `memory_embeddings`
- `recommendations`

The agent retrieves structured NHS context from these tables before generating an answer.

### 2. Distributed Vector Indexing

The project stores Bedrock Titan embeddings in CockroachDB using the `VECTOR(1024)` column type.

Vector search is used to find semantically similar previous memories. This lets the agent answer follow-up questions such as:

```text
What did I ask earlier about capacity pressure?
```

The vector memory layer is implemented through:

- `agent/embeddings.py`
- `agent/memory.py`
- `scripts/test_vector_memory.py`

## AWS Services Used

### 1. Amazon Bedrock

Amazon Bedrock is used for:

- hosted foundation-model response generation
- Titan text embeddings for vector memory

The agent sends retrieved NHS data and memory to Bedrock so the answer is based on stored project context.
